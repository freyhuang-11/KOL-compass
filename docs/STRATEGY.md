> 2026-06-28 经竞品验证后确立。**本文件是产品方向的唯一权威来源**；其它文档（PRODUCT.md / PROJECT_MEMORY.md / AGENT_CONTINUE.md / OUTREACH_FLOW_SPEC.md 等）若与本文件冲突，以本文件为准。
> 大方向已定，**具体执行（功能拆解、排期）未定**。

## 一句话方向
**建联（outreach）只是地基，已经够用。真正值钱、要死磕的是两根柱子：**
1. **建联前分析（选对人）** —— 尽可能做到我们能做到的极致；
2. **建联后管理（管到出单）** —— 投流决策、深度跟踪、数据分析。

> 纯建联没有意义，已是红海。Compass 的命在这两根柱子。

## 竞品验证结论（别再踩）
市场分两派：
- **数据分析派**：Kalodata（2亿画像/500天）、EchoTik（新加坡，营销称10亿、实为画像覆盖量且数据被吐槽不准、明说"找到达人后无执行工具"）、蝉妈妈类。**核心是选品/看数据，不做执行。**
- **建联/执行派**：Cruva、Reacher（美区、全漏斗、真对手）、达连/达秘/Proboost（中国跨境，速度+基础CRM）、花漾（全链路、1000万库、6年）。

**Compass 属执行派。** 关键判断：
- **不去跟数据派拼数据库**（灌水+不准+追不上）。
- 执行派护城河是 workflow/管理，**小、可竞争**。
- 别把竞品营销数（"10亿达人"）当事实。

## TikTok 原生已提供（站肩上，别重造）
- **达人履约率 CFR**（寄样后会不会发的概率）
- **达人样品分 4 维**（履约 / 勤奋 / 出单 / 内容质量）
- **Manage Creators**（近 90 天 GMV / 产出 / 打标签）
- **GMV Max**（算法自动投流）

## 我们的差异化"刀"（组合拳，非单点）

### 柱子①｜建联前分析 = 给"这个商家的商品"算出"该联系谁/该寄样谁"
输入三源：
1. **TikTok 原生**：CFR + 样品分4维 + GMV/类目（官方、不用爬）；
2. **扩展抓的产品契合度**（差异化刀）：达人近 30 天内容**有没有这个商家的品类货** + 评论率 + 购买意向。**TikTok 的分是通用的，给不了"契合你的商品"**；
3. **自有数据**：回复率 / 历史履约（越用越准）。
输出：针对该商家的**出单潜力分 + "值不值得寄样"建议**（保护样品库）。
刀：**产品级契合度 + SEA 跨语言**。

### 柱子②｜建联后管理 = 管到出单 + 投流决策
1. **产出追踪**：约定内容发了没（扩展盯主页 / Manage Creators）→ 喂履约率；
2. **投流决策支持（核心刀）**：每条达人视频拉早期信号（点击率 / 评论速度 / 完播 / 自然出单）→ 对标基准（CTR 2–3%、RPM $25–60）+ 两笔成本（广告费 + 佣金 15–22%）→ 给 **"值得投 / 再看 / 不投"**。**这是没人做成干净决策工具的真空**（Reacher 凑量、Cruva 事后测、GMV Max 黑箱自动）；
3. **出单 / ROI 归因**：联盟订单 API → 每达人/每视频 GMV，投了流的叠广告成本算真 ROI；
4. **复投 / 防流失**：开放合作 **58% 三个月内流失**没人管 → 挑 top 复投、标快流失、自动催。

## 数据采集模型（重要）
- **脚本/服务器爬不行**（扛不住持续看每个达人最近内容）。
- **用 Chrome 扩展**：装在 BD 浏览器、用其已登录会话读 TikTok 前端、**限速**、绑真实工作流、是灰区、随 TikTok 改版长期维护。竞品就是扩展。
- 发现（广）= TikTok 搜索/API 拉候选；深度评分（精）= 扩展只对候选抓。大库靠全商家扩展众包 + 时间累积（网络效应）。

## 不做 / 边界
- **不做"替你自动投流"**（GMV Max 在自动化，打不过平台）；做**投前决策支持 + 投后关系/履约管理**。
- 不跟数据派拼达人库规模。
- 服务商（多商家）形态推迟到上线后；本版单商家多店铺。

## 待验证 / 开放问题
- CFR / 样品分能否走 API 拿、还是只在后台 UI（拿不到就扩展抓）。
- 投流所需的视频早期表现数据来源（TikTok 分析 / 扩展）。
- 护城河（自有回复/履约/出单数据 + 大库）要时间累积；冷启动靠 SG/MY 现成数据当楔子。
- 具体执行：功能拆解与排期未定。**优先级应是：建联前评分 / 投流决策卡 / 复投管理 → 最前；纯建联美化 → 往后。**

## 紧迫性
系统做出来还要做**市场验证**，时间紧。先验证两根柱子的最小可用版能不能让 BD 真感受到价值（Day-1），有正向反馈才滚得动自有数据。
