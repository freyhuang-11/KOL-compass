# KOL Compass 建联流程稿

更新时间：2026-06-23

## 目标

客户从达人库选择达人后，可以基于已同步商品发起建联。建联必须区分三种动作：

1. TikTok 定向邀约：通过 TikTok Shop Affiliate Target Collaboration 创建官方邀约，包含商品、佣金、样品、交付要求。
2. TikTok 私信：通过 TikTok API 给达人发送沟通消息。
3. Email 建联：通过系统邮箱给达人发送邮件；缺少达人邮箱时进入联系方式补充任务。

## 第一性原则

- 商品只能来自已绑定店铺同步数据，不能手填商品。
- 佣金属于商品邀约配置，不属于普通私信模板。
- 定向邀约、私信、Email 是三条不同链路，不能混在一条“消息记录”里。
- 多商品邀约时，每个商品都要能配置标准佣金；广告佣金是可选项。
- 客户可以同时选择 TikTok 私信和 Email 作为通知渠道，但它们只是触达通知，不等同于官方定向邀约。

## 用户主流程

### 入口

达人库列表：

- 单个达人：点击“建联”。
- 批量达人：勾选达人后点击“批量建联”。

进入建联工作台，不使用长滚动大弹窗。

### Step 1：确认达人

展示：

- 已选择达人数量。
- 不可建联达人数量和原因：黑名单、不感兴趣、24 小时内已建联、缺少必要 TikTok open id。
- 当前店铺市场，不允许客户手动选国家。

动作：

- 移除不可建联达人。
- 返回达人库重新选择。

通过条件：

- 至少 1 位可建联达人。

### Step 2：选择商品与佣金

展示：

- 商品来自当前绑定店铺。
- 商品支持多选。
- 每个商品显示：图片、商品名、商品 ID、价格、库存、状态。
- 每个已选商品可配置：
  - 标准佣金率，必填，1-80%。
  - 广告佣金开关，选填。
  - 广告佣金率，开启后必填，1-80%。

动作：

- 添加商品。
- 移除商品。
- 批量修改标准佣金。
- 批量修改广告佣金。

通过条件：

- 至少 1 个可选商品。
- 所有已选商品标准佣金合法。
- 广告佣金开启时佣金合法。

### Step 3：选择建联动作

动作分为两层：

#### A. 官方邀约

- 开关：创建 TikTok 定向邀约。
- 开启后必须配置：
  - 邀约名称。
  - 有效期。
  - 交付形式：短视频、直播，可多选。
  - 样品规则：不寄样、达人申请后审核、自动寄样。
  - 联系人邮箱。

#### B. 触达通知

- TikTok 私信，可选。
- Email，可选。
- 两者可同时选择。
- 至少选择一种触达通知；如果只创建官方邀约，也要明确提示“不会主动通知达人”。

Email 规则：

- 未绑定发信邮箱时，展示“配置邮箱/查看教程”入口。
- 未绑定邮箱不能提交 Email 发送。
- 达人缺少邮箱时，不发送 Email，创建“联系方式补充中”记录。

TikTok 私信规则：

- 只用于发送消息。
- 不负责创建定向邀约。
- 如果 TikTok 返回会话或消息接口错误，记录到该私信记录，不影响定向邀约记录。

通过条件：

- 开启定向邀约或至少选择一个触达通知。
- 如果选择 Email，系统邮箱已配置。

### Step 4：编辑消息与翻译

展示：

- 消息模板选择。
- 中文原文。
- 目标语言，默认按达人市场推荐。
- 翻译预览。

动作：

- 生成翻译。
- 手动编辑翻译。

通过条件：

- 触达通知启用时，消息内容不能为空。

### Step 5：提交

系统生成记录：

- 如果开启 TikTok 定向邀约：
  - 每个达人生成 1 条 `TikTok定向邀约` 记录。
  - 记录状态：待API发送。
  - 提交后只调用 Target Collaboration API。

- 如果选择 TikTok 私信：
  - 每个达人生成 1 条 `TikTok私信` 记录。
  - 记录状态：待API发送。
  - 提交后只调用 TikTok conversation/message API。

- 如果选择 Email：
  - 每个达人生成 1 条 `Email` 记录。
  - 有邮箱：待API发送。
  - 无邮箱：联系方式补充中。
  - 提交后只调用 SMTP 发送接口。

## 建联记录页展示

表格列：

- 达人。
- 商品。
- 渠道：TikTok定向邀约、TikTok私信、Email。
- 状态。
- 发送结果。
- 最后消息。
- 更新时间。
- 操作。

发送结果必须按渠道显示：

- TikTok定向邀约：未提交、已提交、待确认、失败。
- TikTok私信：未提交、已发送、待确认、失败。
- Email：未提交、已发送、待确认、失败、联系方式补充中。

## 失败分支

- Target Collaboration API 缺少官方 ID：状态为 API结果待确认，不得显示为已成功。
- TikTok 私信失败：只影响私信记录，不影响定向邀约记录。
- Email SMTP 失败：只影响 Email 记录，不影响定向邀约或私信记录。
- 达人缺少 Email：创建联系方式补充任务，不把 Email 记录标记为已发送。
- 商品无效或下架：禁止提交定向邀约，提示重新选择商品。

## 设计稿要求

- 不再使用长滚动大弹窗。
- 使用右侧抽屉或独立工作台式页面，分步骤展示。
- 左侧是步骤导航和当前状态，右侧是当前步骤表单。
- 商品选择用干净对象列表，不使用拥挤表格。
- 佣金配置跟随商品行展示，不隐藏在消息区。
- 提交前用摘要区显示将创建几条定向邀约、几条私信、几条 Email。
- 所有界面语言为中文。
- 风格参考 Proboost 店铺管理：白色侧栏、浅灰内容区、低对比描边、紧凑业务列表、少阴影、8px 圆角以内。

## 本阶段核验点

- 流程是否清楚地区分了官方邀约和触达通知。
- 多商品佣金是否在建联前配置，而不是消息发送后补。
- Email 未配置、达人缺邮箱、TikTok API 失败是否都有明确分支。
- 建联记录是否能让客户看懂每个渠道到底发生了什么。
