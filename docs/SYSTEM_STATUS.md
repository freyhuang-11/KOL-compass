## 一、北极星（已确认）

**三个北极星指标**（所有功能都要服务它们）：
1. **回复率** — 触达后达人回不回
2. **样品成功率** — 寄了样出不出内容
3. **成交率** — 产出内容后出不出单

**漏斗**：触达 → **回复** → **寄样** → 产出 → **出单** → 复投
（PRODUCT.md 成功标准同口径：BD 找对人建联 / 运营看履约 / 商家看视频·直播·订单·GMV·ROI 决定催发·终止·复投）

**产品护城河（竞品验证后定）**：不跟数据派拼库；执行派护城河 = **建联前分析(选对人) + 建联后管理(管到出单)** 两根柱子。**纯建联只是地基，已够用**。详见 `STRATEGY.md` / 记忆 core-direction。

## 七、闭环自检：离"选对人→建联→回复→寄样→产出→出单→复投→数据反哺"还差什么

**已通的段**：达人库(选对人的数据底座) → 建联前评分 → 发起建联(出站) → 寄样(官方API)。

**断的关键节点（按对闭环的重要性排序）**：
1. **入站收消息** 🟥⛔ —— 没有它，"回复率"无法自动统计，自动回复无法真触发。**回复率北极星的闭环卡在这。**
2. **出单/ROI 归因** 🟥 —— 没有它，"成交率"无终点数据，整个建联后无法证明价值。**成交率北极星的闭环卡在这。**
3. **内容验收（产出）** 🟥 —— 寄样→产出→出单 中间"产出"这环缺数据。
4. **投流决策 + 复投池** 🟥 —— 建联后管理这根柱子的差异化主体，还没动。
5. **北极星看板** 🟥 —— 三指标无处呈现，价值不可见。

**横切前提**：入站收消息、出单归因都依赖 **①部署公网 ②生产凭证/送审 ③真实合作产生真数据**——这些是外部条件，不全在代码侧。
